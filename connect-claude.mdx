Claude reaches Sempera Phone through the hosted MCP endpoint, in the Claude app as a custom connector or in Claude Code as a remote HTTP server. Both sign in with OAuth and get their own grant.

This guide is setup guidance, not proof that your account can connect; which assistants are available today is on [sempera.org](https://sempera.org/ai-context/). See also [Supported clients](/supported-clients#ai-assistants). If a screen differs from these steps, tell hello@sempera.org and this page will be corrected.

## The Claude app

Claude's current connector screens and plan availability have not been verified here. If your Claude app offers a custom remote MCP connector:

1. Enter `https://api.sempera.org/v1/mcp` as its server URL.
2. Use OAuth with automatic client registration if offered. Sempera supports dynamic registration, not Client Metadata Documents.
3. Sign in to Sempera as the workspace owner, choose the workspace, and approve `phone:read` and `phone:call`; add `phone:text` only if needed. The owner can approve only scopes the client requested.

Sempera recognises `https://claude.ai/api/mcp/auth_callback` as Claude's redirect. Check the actual redirect on the consent page before approving; this recognition is not proof of a completed Claude connection.

## Claude Code

Sempera's setup command is below. The `/mcp` browser sign-in step is guidance only and has not been checked in a real Claude Code build:

```bash
claude mcp add --transport http sempera https://api.sempera.org/v1/mcp
```

Claude Code signs in with a loopback redirect, which the consent page marks as an app on your own computer.

The `@sempera/ai` plugin for Claude Code is a separate kit for building business agents. It has no phone tools; Sempera Phone is reached only through the endpoint above or the REST routes.

## Check the connection

Ask the assistant for your Sempera Phone number and what is left this period. That is a read: it places nothing and needs only `phone:read`. The same read over plain HTTP, with a phone credential from Settings, Connected clients:

<CodeGroup>

```bash cURL
curl https://api.sempera.org/v1/phone-profile \
  -H "Authorization: Bearer $SEMPERA_PHONE_KEY"
```

```python Python
import os, urllib.request

req = urllib.request.Request(
    "https://api.sempera.org/v1/phone-profile",
    headers={"Authorization": f"Bearer {os.environ['SEMPERA_PHONE_KEY']}"},
)
print(urllib.request.urlopen(req).read().decode())
```

```js Node
const res = await fetch("https://api.sempera.org/v1/phone-profile", {
  headers: { Authorization: `Bearer ${process.env.SEMPERA_PHONE_KEY}` },
});
console.log(await res.json());
```

</CodeGroup>

An ordinary workspace API key is refused on the phone routes: every phone credential is a connected client (an OAuth grant, an MCP connection or a REST credential), so it can be revoked on its own.

## What happens on a call

1. The assistant calls `phone_preview_call` (or `POST /v1/phone-tasks/preview`) with the number, the task, the `permitted_actions` and an optional `max_minutes`. Nothing is dialled or reserved. The answer carries an approval link, or `standing: true` if a standing approval covers that number.
2. You open the link signed in to Sempera, read the exact request and approve or decline. The approval is good for five minutes.
3. Unless the preview returned `standing: true`, the assistant reads `phone_get_task` until `approved` is true. It then calls `phone_start_call` with the preview's `id`, `spend_bound_cents` and unchanged call fields. Any change is refused. The task moves to `reserved`, which means queued, not dialling.
4. The assistant follows the task with `phone_get_task` until `completed`, `failed` or `cancelled`. The `result` is marked `untrusted`: it was written from what someone else said.

Texts work the same way with `phone_preview_text` and `phone_send_text`. The full rules, limits and refusal codes are in [Personal phone plan](/phone-plan).

## Use the phone

In Settings \> Connected clients, check that Claude holds `phone:read` and `phone:call`; add `phone:text` only for texts. OAuth scopes must be requested by Claude and approved on Sempera's consent page; reconnect with the required scopes if they are missing. For a Claude Code bearer connection, choose **Claude Code**, **Read** and **Phone tools (owner approval required)** under **Connected AI clients**, then use the newly created key. Existing keys are not upgraded.

Follow [Your first call](/phone-plan#your-first-call) for plan and number setup, owner approval, the call and its result. A connection alone is not a ready phone line. The [limits](/phone-plan#limits) and [refusal help](/phone-plan#if-a-call-is-refused) explain when a call can run.

## Disconnect

Open Settings, Connected clients in the Sempera App and revoke the client. That ends its credential at once and leaves every other assistant working.
