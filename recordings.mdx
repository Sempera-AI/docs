Sempera stores a phone call's audio when the workspace's data policy has recording on, and keeps it for the retention period the workspace owner set. The API tells you whether a recording exists and hands out a short-lived link to it; it does not stream audio itself.

## Which calls keep audio

The following admission behavior applies to call-gated workspaces, including non-trial workspaces using spend reservations. Record calls means the agent's published setting, not an unpublished draft. Transcripts remain subject to the existing transcript retention policy.

| Call type | Setting or workspace | Before this fix | After this fix |
| --- | --- | --- | --- |
| Public demo link | Non-trial, Record calls ON | Transcript only | Audio plus transcript, with the spoken notice |
| Website web voice | Non-trial, Record calls ON | Transcript only | Audio plus transcript, with the spoken notice |
| Public demo link or website web voice | Non-trial, Record calls OFF | Transcript only | Unchanged: no audio, transcript kept |
| Any browser call | Free-trial reservation | Transcript only | Unchanged: never audio recorded |
| Console Test call or simulator | Non-trial, Record calls ON | Transcript only when gated | Audio plus transcript, with the spoken notice |
| Console Test call or simulator | Non-trial, Record calls OFF | Transcript only when gated | Unchanged: no audio, transcript kept |
| Real phone call | Any setting | Existing phone behavior | Unchanged by this fix |
| Workspace that is not call-gated | Any browser setting | Existing browser audio evidence | Unchanged by this fix |

A recording-ON browser version without a deterministic spoken recording notice fails closed: no audio is kept. The spoken notice remains "Just a heads-up, this call may be recorded." The written browser notice remains "This call may be recorded and transcribed." Neither notice is an optional setting.

A free-trial or otherwise unrecorded call overrides recording-ON compiled instructions for that call. Definite recording claims are corrected before speech. On a recorded call the recording notice is not removed.

Phone follow-up: gated phone calls are also affected by the old unconditional recording-disabled flag. This fix deliberately retains their existing refusal rather than changing phone consent or recording behavior without its own review. Ungated browser previews currently keep audio even with the published setting OFF; changing that call-service behavior is outside this card.

For a completed browser session, inspect `GET /v1/sessions/{id}` for `has_audio`, `recording`, `runtime.recording.enabled`, transcript turns, and `tcpa_misses`. A successful admission is not proof of a successful hosted audio upload. Verify the finished session and playback before claiming a recording exists. Retention, access controls and deletion rules below are unchanged.

## Whether a call has a recording

A phone call's `recording` field (`GET /v1/calls`, `GET /v1/calls/{call_id}`, `GET /v1/sessions/{id}`) reads:

```json
{"id": "8f6c...", "state": "available", "expires_at": "2026-12-28T12:00:00+00:00",
 "deleted_at": null, "delete_reason": null, "access_ends_at": null}
```

| `state` | Meaning |
| --- | --- |
| `none` | No recording was stored (`id` is null) |
| `available` | Stored and playable |
| `held` | Kept because a legal hold is on the workspace, whatever its expiry date |
| `expired` | Past its expiry date and awaiting deletion |
| `access_ended` | Still kept, but the workspace's recording security setting has ended access to it |
| `deleted` | Deleted; `deleted_at` and `delete_reason` say when and why |

`id` is the value for `{recording_id}` below. `recording_stored` on the `call.completed` webhook ([Webhooks](/webhooks)) says whether one was stored.

## Browser and preview session audio

A completed browser, demo-link or simulated voice session can instead carry `recording.source: evidence`. Its `id` identifies the session evidence, and `channels.agent` and `channels.caller` provide the available channel URLs and lengths in seconds. A channel is listed only while its stored WAV file exists. Recording-off and typed sessions without stored audio have no recording link. Retention removes channel links and can leave `state: deleted` with the deletion reason. Reading a historical session does not rewrite it.

These channel URLs use the App's existing signed-in audio access checks. They are separate from the phone recording IDs accepted by the download route below; an API key does not grant playback through a browser channel URL.

## The download link

| Route | Scope | Notes |
| --- | --- | --- |
| `GET /v1/recordings/{recording_id}` | `calls:read` | A signed link that is valid for 5 minutes, for a recording your workspace owns |

```json
{"object": "recording", "id": "8f6c...", "download": true,
 "url": "/api/recordings/audio?id=8f6c...&exp=1790688433&sig=...&download=1",
 "expires_at": "2026-09-29T13:27:13+00:00"}
```

The route looks the recording up before it signs anything. `recording_id` must be a recording of a phone call on an agent the credential can read, in the workspace that agent belongs to; take ids from the `recording` field of a call you can read. An id that does not exist and an id that belongs to another workspace both answer `404 not_found`, identically, and no link is made for either. A recording that was deleted answers `410 gone` with `reason: deleted`, one whose access ended under the workspace's recording security answers `410 gone` with `reason: access_ended`, and a workspace that plays recordings only to its own signed-in members answers any other caller `403 forbidden` with `reason: members_only`; none of them is signed. Every link this route issues is recorded in the workspace's audit log, as the App's are.

`url` is a path on the Sempera App (`https://app.sempera.org`), not on this API ([API overview](/api-overview)). The App checks the link's signature, checks its expiry, and requires a signed-in member of the workspace that owns the recording before it sends any audio. The link carries no access by itself. The audio path answers `410` for a recording that was deleted or whose access ended, and every play is recorded in the workspace's audit log.

The signature is bound to the identity that asked for the link, and only that identity can use it:

| Who asked | Who can play the link |
| --- | --- |
| A signed-in member, with their App session (the App serves `/v1` on its own origin) | That member, while signed in and still a member of the owning workspace |
| An API key | Nobody. The audio path does not accept an API key (`403`), and a signed-in member presenting a key's link is a different identity (`403`) |

So with an API key this route confirms that a recording exists and is yours, but it does not deliver audio: downloading call audio server to server is not offered. To listen, open the call in the App.

Recording on or off, the retention period, legal holds, how long access lasts and deletion are the workspace owner's settings in the App; no `/v1` route changes them.
