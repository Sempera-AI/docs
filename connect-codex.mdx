Codex reads its MCP servers from `config.toml`. Add Sempera once, sign in through your browser, and Codex can preview calls and texts for you to approve.

This guide is setup guidance, not proof that your account can connect; which assistants are available today is on [sempera.org](https://sempera.org/ai-context/). See also [Supported clients](/supported-clients#ai-assistants). If a screen differs from these steps, tell hello@sempera.org and this page will be corrected.

## Add the server and sign in

Add the server to `~/.codex/config.toml`. This URL/config shape is included in Sempera's setup guidance. Codex's current OAuth commands and flags have not been verified here.

```toml
[mcp_servers.sempera]
url = "https://api.sempera.org/v1/mcp"
```

If your Codex build offers OAuth, use its MCP sign-in instructions with dynamic client registration and approve `phone:read` and `phone:call` on Sempera's consent page. Sempera accepts native loopback redirects. Otherwise use the bearer connection below.

## Or use a credential

1. In Settings \> Connected clients, under **Connected AI clients**, select **Codex** and **Read** access. Turn on **Phone tools (owner approval required)** and choose **Connect client**. Store the key shown once in your local `SEMPERA_PHONE_KEY` environment variable, using your usual secret manager rather than committing it.
2. Use the TOML below. This bearer configuration is present in Sempera's setup guidance; loading it in a real Codex build remains unverified. The key works on MCP only and adds all three phone scopes to the read scopes. An ordinary workspace API key is refused on the phone tools.
3. If replacing an older connection, update the key in Codex and disconnect the old credential. Creating a new one does not upgrade or revoke the old one.

```toml
[mcp_servers.sempera]
url = "https://api.sempera.org/v1/mcp"
bearer_token_env_var = "SEMPERA_PHONE_KEY"
```

## The phone tools Codex sees

| Tool | Permission |
| --- | --- |
| `phone_get_profile`, `phone_get_task` | `phone:read` |
| `phone_preview_call`, `phone_start_call`, `phone_cancel_task` | `phone:call` |
| `phone_preview_text`, `phone_send_text`, `phone_get_thread` | `phone:text` |

The `@sempera/ai` Codex plugin is a business agent-building kit and has no phone tools.

## Check the connection

Ask the assistant for your Sempera Phone number and what is left this period. That is a read: it places nothing and needs only `phone:read`. The same read over plain HTTP, with a phone credential from Settings, Connected clients:

<CodeGroup>

```bash cURL
curl https://api.sempera.org/v1/phone-profile \
  -H "Authorization: Bearer $SEMPERA_PHONE_KEY"
```

```python Python
import os, urllib.request

req = urllib.request.Request(
    "https://api.sempera.org/v1/phone-profile",
    headers={"Authorization": f"Bearer {os.environ['SEMPERA_PHONE_KEY']}"},
)
print(urllib.request.urlopen(req).read().decode())
```

```js Node
const res = await fetch("https://api.sempera.org/v1/phone-profile", {
  headers: { Authorization: `Bearer ${process.env.SEMPERA_PHONE_KEY}` },
});
console.log(await res.json());
```

</CodeGroup>

An ordinary workspace API key is refused on the phone routes: every phone credential is a connected client (an OAuth grant, an MCP connection or a REST credential), so it can be revoked on its own.

## What happens on a call

1. The assistant calls `phone_preview_call` (or `POST /v1/phone-tasks/preview`) with the number, the task, the `permitted_actions` and an optional `max_minutes`. Nothing is dialled or reserved. The answer carries an approval link, or `standing: true` if a standing approval covers that number.
2. You open the link signed in to Sempera, read the exact request and approve or decline. The approval is good for five minutes.
3. Unless the preview returned `standing: true`, the assistant reads `phone_get_task` until `approved` is true. It then calls `phone_start_call` with the preview's `id`, `spend_bound_cents` and unchanged call fields. Any change is refused. The task moves to `reserved`, which means queued, not dialling.
4. The assistant follows the task with `phone_get_task` until `completed`, `failed` or `cancelled`. The `result` is marked `untrusted`: it was written from what someone else said.

Texts work the same way with `phone_preview_text` and `phone_send_text`. The full rules, limits and refusal codes are in [Personal phone plan](/phone-plan).

## Use the phone

Check Codex in Settings \> Connected clients. Calls need `phone:read` and `phone:call`. The bearer connection's **Phone tools (owner approval required)** option grants these and `phone:text`; for OAuth request only the scopes needed. Recreate a bearer connection or repeat OAuth consent if permissions are missing, then update Codex's credential.

Follow [Your first call](/phone-plan#your-first-call) for plan and number setup, owner approval, the call and its result. A connection alone is not a ready phone line. See the [limits](/phone-plan#limits) and [refusal help](/phone-plan#if-a-call-is-refused).

## Disconnect

Open Settings, Connected clients in the Sempera App and revoke the client. That ends its credential at once and leaves every other assistant working.
