How you can connect to Sempera today, and how much of each road Sempera has actually proven. Read the status column before you plan around a client: "supported" and "guidance only" are different promises, and this page keeps them apart.

## What the statuses mean

| Status | What it means |
| --- | --- |
| Supported | The road is part of the documented contract and works with any compliant client. |
| Guidance only | Sempera serves a ready-made setup snippet for this client. Sempera has not recorded a connection made from the real client, so a snippet that fails is a bug to report, not a known-good path. |
| Unverified | The server side exists and is tested against the published standards, but no real account has completed it. A failure is a bug to report, not a known-good path. |
| Not available | It does not exist yet. Nothing on this page promises a date. |

## Ways to connect

| Road | What you use | How you sign in | Status |
| --- | --- | --- | --- |
| Any HTTP client | The REST API under `/v1`, described by `https://api.sempera.org/openapi.json`. Curl, server code in any language, or a coding agent's own HTTP tool. | API key, sent as a bearer token | Supported |
| A browser voice conversation | Your server calls `POST /v1/sessions`, then the page connects with `@sempera/web` ([Web SDK](/web-sdk)), or the lower-level realtime web client. | A short-lived token for one room | Supported. `@sempera/web` version 0.1.0 is published on npm (released 2026-11-16). |
| A webhook receiver | Any HTTPS server that verifies `X-Sempera-Signature` ([Webhooks](/webhooks)). | The signature, with your endpoint's secret | Supported |
| An AI assistant over MCP | `POST /v1/mcp`, approved on a consent page. See [AI assistants](#ai-assistants). | OAuth | Unverified |
| A coding-agent client over MCP | `POST /v1/mcp`, with a setup snippet from `GET /v1/mcp/clients/{client}` or the `mcp_client_setup` tool. See the MCP section of [getting started](/getting-started#connecting-a-coding-agent-mcp). | API key, sent as a bearer token | Guidance only, per client below |

For the browser package:

```bash
npm install @sempera/web
```

The API key is never accepted as a browser credential. Your server authenticates and authorizes the customer, then issues the short-lived token through `POST /v1/sessions`. Public-key admission is refused: `start()` rejects with `public_key_unavailable` before accessing the microphone or network. Use the server-issued token flow in [Web SDK](/web-sdk) instead.

## Coding-agent clients over MCP

Every client below receives the same endpoint and the same header; only the file or command that holds them differs. Pass the client's id to `GET /v1/mcp/clients/{client}` to get the exact snippet for it.

| Client | Id | Setup snippet served | Connection verified from the real client | Status |
| --- | --- | --- | --- | --- |
| Claude Code | `claude-code` | Yes, a shell command | Not recorded | Guidance only |
| Claude Desktop | `claude-desktop` | Yes, a JSON config using a remote-server bridge | Not recorded | Guidance only |
| Cursor | `cursor` | Yes, a JSON config | Not recorded | Guidance only |
| VS Code | `vs-code` | Yes, a JSON config that prompts for the key | Not recorded | Guidance only |
| Windsurf | `windsurf` | Yes, a JSON config | Not recorded | Guidance only |
| Gemini CLI | `gemini-cli` | Yes, a JSON config | Not recorded | Guidance only |
| Codex | `codex` | Yes, a TOML config | Not recorded | Guidance only |
| Any other client | `other` | Yes, a plain HTTP request | Not recorded | Guidance only |

`GET /v1/mcp/clients/{client}` and `mcp_client_setup` return setup guidance; a generated snippet is not proof of a real-client connection. The assistant guides below cover the phone journey. Use Settings \> Connected clients \> **Connected AI clients** to create a bearer MCP connection. For phone use, choose **Read** and enable **Phone tools (owner approval required)** before creating the key. This adds `phone:read`, `phone:call` and `phone:text` to the read scopes, rather than creating a phone-only credential. An older key is not upgraded.

The MCP endpoint accepts `agents:read` or a phone scope; each tool then needs its own scope. A CI key is refused ([Authentication and credentials](/authentication)). An ordinary workspace API key cannot use the phone tools. Keep a connection key in the client's secret store or an environment variable, never in a committed file.

## AI assistants

There are four assistant entries: Claude, ChatGPT/Codex, Grok Bot and Muse. ChatGPT and Codex have separate guides because their connection methods differ. Each connection gets its own credential, so ending one leaves the others working.

No real assistant account has completed the full sign-in, tool listing, approved call, result read and revocation journey. The server's phone profile and call preview have been exercised over MCP; that does not prove assistant-specific connectivity or a handset ring. A client moves out of Unverified only when that full journey is recorded with a date and app version.

| Assistant | How it connects | Guides | Status |
| --- | --- | --- | --- |
| Claude | MCP with OAuth; Claude Code can also use a bearer MCP key | [Claude](/connect-claude) | Unverified |
| ChatGPT/Codex | ChatGPT: MCP with OAuth. Codex: MCP config with OAuth or a bearer MCP key | [ChatGPT](/connect-chatgpt), [Codex](/connect-codex) | Unverified |
| Grok Bot | MCP if its app offers OAuth or a secure bearer-header field | [Grok Bot](/connect-grok) | Unverified; client UI and authentication not established |
| Muse | REST with a scoped credential, if its app can build a custom API connector | [Muse](/connect-muse) | Unverified; connector UI not established |

The guides label assistant-side setup that has not been verified. They do not promise a connector screen or account entitlement. Connecting a client does not give the phone agent that client's memory, chats or subscription.

### Phone permissions

| Scope | What it allows |
| --- | --- |
| `phone:read` | Read the number, plan state, allowance and call tasks/results |
| `phone:call` | Preview calls, start approved calls and cancel tasks |
| `phone:text` | Preview texts, send approved texts and read threads |

OAuth and device-code onboarding default to `phone:read`. Calls need both read and call scopes to complete the journey. OAuth can grant only scopes the host requests; approve again if they need changing. In Settings \> Connected clients, the Muse credential form has separate **See the number and results**, **Place calls** and **Send texts** switches. No existing credential gains permissions automatically, and no phone scope can approve a request or buy a plan.

See the [phone tools](/connect-mcp#phone-tools), then follow [Your first call](/phone-plan#your-first-call) for the plan, number, owner approval and result. Public purchase is not open; a connection does not activate a phone line.

## Not available today

- **Third-party SDKs.** Use the official TypeScript and Python libraries, which are on npm and PyPI (see [SDKs](/sdks)). Sempera does not verify clients produced by third-party generators.
- **Directory listings and marketplace plugins.** Sempera does not offer a directory listing or a marketplace plugin for connecting. A setup snippet is the supported way to connect a coding agent.
- **A separate test host.** There is one API hostname ([API overview](/api-overview)). Use a workspace you can afford to experiment in, and read the idempotency rules before you automate writes ([Errors and limits](/errors-and-limits)).

## Keeping this page honest

When a client's connection has been checked from the real client, its row says so with the date and the client version. Until then the cell says "Not recorded", and a snippet is a starting point rather than a promise.
