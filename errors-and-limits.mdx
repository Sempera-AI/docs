## Error envelope

The standard REST refusal has this shape (protocol and compatibility exceptions are listed below):

```json
{"error": {"code": "insufficient_scope", "message": "this credential cannot agents publish", "request_id": "req_...", "scope": "agents:publish"}}
```

| Code | Status | Meaning |
| --- | --- | --- |
| `authentication_required` | 401 | No credential |
| `invalid_credential` | 401 | A key that is unknown, expired or revoked |
| `insufficient_scope` | 403 | The key lacks the route's scope |
| `forbidden` | 403 | The role cannot do this |
| `workspace_suspended` | 403 | The workspace is paused, so its agents take no new actions. Reads and exports still work |
| `csrf_failed` | 403 | An App-session write without its CSRF proof |
| `validation_failed` | 400 | A field is missing or wrong (`field` names it) |
| `AGENT_ENV_UNPINNED` | 400 | The call asked for the production version of an agent that has no version pinned to production |
| `credits_exhausted` | 402 | Not enough credits for this building action, so nothing started. Carries `needed`, `balance`, `debt` and, where buying can work, `buy_path`. Live agents are not affected ([Billing boundaries](/billing-boundaries)) |
| `not_found` | 404 | No such resource in your scope |
| `method_not_allowed` | 405 | This route does not support the HTTP method; `Allow` lists supported methods |
| `conflict` | 409 | A rule refused it (a stale draft, a live version, a taken number); `reason` may carry a finer code |
| `idempotency_key_reused` | 409 | Same key, different request |
| `gone` | 410 | It existed and is no longer served (a deleted recording, or one whose access ended); `reason` says which |
| `payload_too_large` | 413 | The request body exceeds the route's size limit |
| `rate_limited` | 429 | A request or feature budget is exhausted; use `Retry-After` or the error's `retry_after_s` when present |
| `CALL_RL_PLAN_CONCURRENCY` | 429 | The plan's limit on calls at once is reached ([phone plan](/phone-plan)) |
| `CALL_RL_PLAN_HOURLY` | 429 | The plan's calls per hour are used |
| `CALL_RL_PLAN_DAILY` | 429 | The plan's calls for today are used |
| `CALL_RL_PLAN_DAILY_MINUTES` | 429 | The plan's call minutes for today are used |
| `CALL_RL_PLAN_ALLOWANCE` | 429 | The plan's minutes are used (limited mode) |
| `SMS_RL_PLAN_HOURLY` | 429 | The plan's texts per hour are used |
| `SMS_RL_PLAN_DAILY` | 429 | The plan's texts for today are used |
| `SMS_RL_PLAN_ALLOWANCE` | 429 | The plan's text segments are used (limited mode) |
| `PHONE_PLAN_INACTIVE` | 403 | No active phone plan |
| `PHONE_DESTINATION_BLOCKED` | 403 | The plan cannot reach that number |
| `PHONE_COST_UNKNOWN` | 503 | That destination or route has no approved cost, so nothing started |
| `PHONE_APPROVAL_REQUIRED` | 403 | The account owner has not approved this yet |
| `PHONE_APPROVAL_INVALID` | 403 | The request does not match what was previewed |
| `PHONE_APPROVAL_EXPIRED` | 410 | The approval expired. Preview again |
| `PHONE_FUNDING_NOT_LIVE` | 403 | A test payment cannot fund a real call or text |
| `PHONE_AGENT_UNPINNED` | 409 | The owner has not pinned an agent to the plan |
| `PHONE_NUMBER_MISSING` | 409 | The plan has no number ready |
| `PHONE_RECIPIENT_OPTED_OUT` | 403 | The recipient texted STOP |
| `PHONE_OUTSIDE_HOURS` | 409 | Outside calling hours |
| `PHONE_TEXTING_UNAVAILABLE` | 409 | The line's number cannot send texts, so the text preview was refused before any approval |
| `capability_unavailable` | 501 | Not offered on this platform. `POST /v1/calls` also answers it with `reason: do_not_contact` when the number is on the workspace's do-not-contact list ([Sessions and calls](/sessions-and-calls)) |
| `provider_failed` | 502 | A provider behind the API failed |
| `provider_timeout` | 504 | A service Sempera called did not answer in time |
| `owner_setup_required` | 503 | A feature the workspace owner has not configured yet |
| `credits_unavailable` | 503 | The credit balance could not be read, so nothing started. Live agents are not affected |
| `service_unavailable` | 503 | A required service or stored record cannot be read right now; check the operation's state before retrying a write |
| `internal_error` | 500 | Quote the `request_id` to support |

The plan limit codes (`CALL_RL_PLAN_*` and `SMS_RL_PLAN_*`) carry no figures here; the current figures are on the [pricing page](https://sempera.org/pricing/).

Quote `X-Request-Id` to support. Branch on the stable code, not the human-readable message.

### OAuth protocol errors

OAuth registration and token exchange use `{"error": "<name>", "error_description": "..."}`, not the REST envelope. Authorization can return an error in the registered redirect's query parameters instead. These are the protocol errors the API emits:

| OAuth error | Meaning |
| --- | --- |
| `invalid_client_metadata` | Registration is not a JSON object or requests unsupported client metadata |
| `invalid_redirect_uri` | Registration supplies no valid redirect list, too many redirects or an unsafe redirect |
| `invalid_client` | The client is unknown or its authentication failed; client authentication failures on token exchange are 401 |
| `invalid_request` | Required protocol inputs are missing, malformed, repeated or do not match the registered redirect |
| `unsupported_response_type` | Authorization requested something other than the code flow |
| `unsupported_grant_type` | Token exchange requested something other than `authorization_code` or `refresh_token` |
| `invalid_target` | The requested resource is not this MCP endpoint or does not match the grant |
| `invalid_scope` | A scope cannot be granted, or refresh tried to widen the grant |
| `invalid_grant` | A code or refresh token is invalid, expired, already used or fails its binding checks |
| `access_denied` | The person denied consent, or the consent request was already answered or expired |

A schema declaring a possible HTTP status does not introduce another error name. Service-only ingress has its own proof and response formats, not a second set of developer error codes ([Webhooks](/webhooks)).

### MCP protocol errors

MCP transport can return JSON-RPC `{"jsonrpc": "2.0", "id": ..., "error": {"code": number, "message": "..."}}`:

| JSON-RPC error | Meaning |
| --- | --- |
| `-32600` | Invalid request: wrong JSON-RPC version, invalid id or missing id on a request that is not a notification |
| `-32601` | Unknown method |
| `-32602` | Invalid parameters, such as an unissued cursor, unknown UI resource or arguments that are not an object |
| `-32000` | A tool request was refused, or the requested operator panel is not built on this deployment |

Authentication, scope and transport guards can still return REST errors. Tool results can instead set `isError: true` and carry the REST or compatibility refusal from the underlying operation. See [MCP for coding agents](/connect-mcp) for the transport contract.

### Compatibility errors

Compatibility routes can answer `{"data": null, "errors": [{"error": "<name>", "message": "..."}]}`. Names are case-sensitive; they are not aliases for the REST `code` field. Some reads put an error beside partial data instead of failing the HTTP request.

| Compatibility error | Meaning |
| --- | --- |
| `bad_request`, `validation_error`, `BAD_REQUEST` | Invalid fields, filters, paging or body; inspect the route's message |
| `not_found`, `NOT_FOUND` | No such resource in this credential's scope |
| `forbidden` | This compatibility feature is unavailable to the workspace |
| `conflict`, `CONFLICT` | A duplicate, stale edit or resource state prevents the operation |
| `DEPRECATED_FINAL` | Subaccounts are retired and unavailable |
| `INVALID_TYPE` | The organization-key lookup accepts only `type: org` |
| `INVALID_TARGET` | The organization-key lookup needs a workspace id as `target_id` |
| `KB_ERROR` | A knowledge source is missing, inaccessible or cannot accept the requested content edit |
| `stale_content` | The knowledge source changed; read `current_version_id` before saving again |
| `INVALID_NAME` | A branch name is invalid or reserved |
| `BRANCH_EXISTS` | An open branch already has that name |
| `BRANCH_NOT_FOUND` | The branch being deleted is missing or outside scope |
| `INVALID_RESOLUTIONS` | A rebase resolution is malformed or fails draft validation |
| `UNRESOLVED_CONFLICTS` | A rebase conflict still needs a resolution |
| `REBASE_STALE` | Main changed since the rebase preview, or its head was not supplied correctly |
| `BRANCH_BEHIND` | Main moved beyond the branch's base; rebase before merging |
| `NO_CHANGES` | The branch has no changes to merge |
| `UNAVAILABLE` | Branch storage is unavailable |
| `TOO_MANY_REQUESTS` | Disposition test-run concurrency or alignment frequency is at its limit |
| `SERVICE_UNAVAILABLE` | Disposition storage or its reader is unavailable |
| `DISPOSITION_ALIGN_NOT_READY` | Alignment needs a finished disposition run with a correction |
| `OWNER_SETUP_REQUIRED` | A disposition estimate has no usable model pricing |
| `media_server_unreachable` | The active-call service could not be reached; an empty result is not proof of no calls |

A failed snippet test returns a `snippet_test` record with `error_code`, not a REST refusal: `arguments` (invalid inputs), `timeout` (time limit), `sandbox` (execution failure), `output_too_large` (result too large), `refused` (disallowed expression), `schema` (result does not match its schema) or `busy` (no execution slot became available). See [Code snippets](/snippets). Live transcript frames can carry a plain `error` sentence instead of any code ([Live calls and live transcripts](/live-call-streams)).

### Reasons

A refusal can carry a finer `reason` beside its `code`. A reason is stable and safe to branch on; the `message` is for people and may change.

| Reason | Code and status | Where | Meaning |
| --- | --- | --- | --- |
| `invalid_voice_id` | `validation_failed`, 400 | A draft, a session, a voice's detail and preview, a favorite | The value looks like a Sempera voice id (`voice_` then lowercase letters and digits) and is not one Sempera issued. Choose an id from `GET /v1/voices`. The App's own routes answer it as `code: invalid_voice_id` |
| `voice_unknown`, `engine_unavailable`, `engine_not_allowed`, `catalog_unavailable`, `preview_unavailable` | `validation_failed` or `conflict` | Voice reads, previews and drafts | Why a voice or its engine cannot be used right now, in Sempera's words. None names a speech supplier or its id for the voice |
| `consent_missing`, `consent_no_workspace`, `consent_store_unavailable` | `forbidden`, with `code: voice_consent_required` on the App's routes | A custom voice | The consent record a custom voice needs is absent or unreadable |
| `stale_draft` | `conflict`, 409 | `PATCH /v1/agents/{id}/draft`, MCP `update_agent_draft` | Your `expect_revision` is older than the draft. Read it again and merge |
| `stale_webhook` | `conflict`, 409 | `PATCH /v1/webhooks/{id}` | Your `expected_updated_at` is older than the endpoint's. The answer carries the `updated_at` now on file |
| `do_not_contact` | `capability_unavailable`, 501 | `POST /v1/calls` | The number is on the workspace's do-not-contact list |
| `judge_unavailable`, `judge_not_independent` | `service_unavailable`, 503 | `POST /v1/evals/run`, `POST /v1/evals/quick-run` | No judging model is reachable, or the judge is not independent of the builder. No calls were scored |

An engine in a draft, a session or a runtime reading is named by a sealed Sempera name (`engine_` then letters and digits) and a voice by its Sempera voice id; a refusal never repeats the engine or the engine's own id.

### A paused workspace

While a workspace is paused, a signed-in member gets `403 workspace_suspended` on every request that would take a new action, and still reads and exports. Its API keys behave differently: a key of a paused workspace is refused as an unknown key would be, with `401 invalid_credential`, on reads as well as writes, and works again unchanged when the workspace is restored. Do not rotate or reissue keys in response to that 401 without first checking the workspace's status in the App.

A workspace that only ever used API keys still has a road to its data while paused. The workspace owner signs in to the Sempera App, where the agent export, the call export and the call list keep working, and where the data deletion and workspace closure paths stay open. Nothing is deleted by a pause.

## Pagination

Most Sempera-native list routes take `limit` (1 to 200, default 50) and `cursor`. Responses are `{"object": "list", "data": [...], "has_more": true, "next_cursor": "..."}`. Pass `next_cursor` back unchanged; cursors are opaque. Compatibility facade routes keep their observed external envelopes, including `tools`/`hasMore`/`nextCursor`, `data.count`/`data.integrations`, `data` plus `errors`, and `voices`-only shapes. Check `openapi.json` for the exact response shape on each route.

## Idempotency

Use `Idempotency-Key` (up to 255 characters) on operations whose `openapi.json` parameters list that header. This includes agent creation, publication and rollback, sessions, calls, tool tests, test runs and webhook creation and resend. The header is required for outbound calls, SMS writes and webhook resends; consult the operation's contract before sending.

A retry with the same key, method, path and exact body bytes replays a saved answer with `Idempotent-Replayed: true`. Use the same JSON bytes, not just equivalent parsed values. Reusing a key for a different request is `409 idempotency_key_reused`. A concurrent retry while the first request is still running is `409 conflict` with `reason: request_in_progress`. Keys live 24 hours and are scoped to your workspace.

Successful JSON answers are saved. Most refused or failed operations release the key so a retry can run again. Outbound calls also save a definite carrier refusal, such as busy or unanswered, so repeating it does not dial again. An uncertain call, SMS send or webhook resend keeps its reservation rather than becoming eligible for a stale retry. Check the recorded outcome before starting new work with a different key.

## Rate limits

| Subject | Limit |
| --- | --- |
| Per API key | 600 requests per minute |
| Anonymous (public routes), per IP | 60 requests per minute |
| Carrier media-stream ingress, per IP (its own budget, never the anonymous one) | 600 requests per minute |

These are the default request budgets; deployment settings may change them. Requests that reach the limiter carry `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` (Unix seconds). A request-budget `429` carries `Retry-After` in seconds. Earlier authentication or routing refusals may have no rate-limit headers. Feature-specific `429` responses may instead report `retry_after_s` in the error. Back off exponentially. If the request counter cannot be read, the request is refused with `503 service_unavailable` and `Retry-After`, and nothing ran.

Separately from these request limits, a workspace owner may cap the outbound calls the workspace places per UTC hour and per UTC day. `POST /v1/calls` over a cap answers `429 rate_limited` with `retry_after_s` in the error, and places nothing; if the cap cannot be read it answers `503 service_unavailable` and places nothing ([Owner features in the App](/app-features)).

## Body size

JSON bodies read through the shared JSON parser are limited to 1 MiB. Knowledge files have a 25 MiB default maximum; a workspace or deployment can set a smaller upload limit. An oversized knowledge file is refused as `409 conflict`, not necessarily `413 payload_too_large`.
