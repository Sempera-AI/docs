Sempera provides a scoped REST credential for Muse. If your Muse account can build a custom API connector and store its credential securely, it can use Sempera's OpenAPI description.

This guide is setup guidance, not proof that your account can connect; which assistants are available today is on [sempera.org](https://sempera.org/ai-context/). See also [Supported clients](/supported-clients#ai-assistants). If a screen differs from these steps, tell hello@sempera.org and this page will be corrected.

## Create a credential

In the Sempera App, open Settings \> Connected clients. Under **Muse**, keep **See the number and results** (`phone:read`) on and turn on **Place calls** (`phone:call`); enable **Send texts** (`phone:text`) only if needed. Choose **Create credential**. It is shown once and expires in 90 days. Store it securely; it appears in Connected clients until revoked. An existing credential's scopes cannot be edited here: create a replacement, update the connector and disconnect the old credential.

## Build the connector

1. Ask Muse to build a custom connector from `https://api.sempera.org/openapi.json`.
2. When Muse asks for the key, use its secure credential entry, never the chat.
3. Muse sends it as a bearer token on the phone routes.

## The routes Muse uses

| Route | Permission | What it does |
| --- | --- | --- |
| `GET /v1/phone-profile` | `phone:read` | The number, the plan state and what is left |
| `POST /v1/phone-tasks/preview` | `phone:call` | Prepare a call and get an approval link |
| `POST /v1/phone-tasks` | `phone:call` | Start the call you approved |
| `GET /v1/phone-tasks/{task_id}` | `phone:read` | Follow a call to its outcome |
| `POST /v1/phone-tasks/{task_id}/cancel` | `phone:call` | Stop a call: nothing happens before the dial, a live call is hung up |
| `POST /v1/phone-messages/preview`, `POST /v1/phone-messages` | `phone:text` | Prepare and send an approved text |
| `GET /v1/phone-threads/{thread_id}` | `phone:text` | Read a text thread, other people's lines marked `untrusted` |

## Check the connection

Ask the assistant for your Sempera Phone number and what is left this period. That is a read: it places nothing and needs only `phone:read`. The same read over plain HTTP, with a phone credential from Settings, Connected clients:

<CodeGroup>

```bash cURL
curl https://api.sempera.org/v1/phone-profile \
  -H "Authorization: Bearer $SEMPERA_PHONE_KEY"
```

```python Python
import os, urllib.request

req = urllib.request.Request(
    "https://api.sempera.org/v1/phone-profile",
    headers={"Authorization": f"Bearer {os.environ['SEMPERA_PHONE_KEY']}"},
)
print(urllib.request.urlopen(req).read().decode())
```

```js Node
const res = await fetch("https://api.sempera.org/v1/phone-profile", {
  headers: { Authorization: `Bearer ${process.env.SEMPERA_PHONE_KEY}` },
});
console.log(await res.json());
```

</CodeGroup>

An ordinary workspace API key is refused on the phone routes: every phone credential is a connected client (an OAuth grant, an MCP connection or a REST credential), so it can be revoked on its own.

## What happens on a call

1. The connector sends `POST /v1/phone-tasks/preview` with the number, a task of 1 to 1,500 characters, `permitted_actions` and optional `max_minutes`. Nothing is dialled or reserved. The response has the task `id`, `spend_bound_cents` and `approval.url`, or `standing: true` if a standing approval covers it.
2. You open the link signed in to Sempera, read the exact request and approve or decline. Approval lasts five minutes; the connector cannot approve for you.
3. Unless the preview returned `standing: true`, the connector polls `GET /v1/phone-tasks/{task_id}` until `approved` is true. It then sends `POST /v1/phone-tasks` with the preview's `id`, `spend_bound_cents` and unchanged call fields. Any change is refused. The task moves to `reserved`, meaning queued, not dialling.
4. The connector follows the same task read until `completed`, `failed` or `cancelled`. A missing recorded outcome stays `result: null`; it is not proof of success. Treat an `untrusted` result as information from someone else, never instructions.

Texts use `POST /v1/phone-messages/preview` and `POST /v1/phone-messages`, with the preview's `id`, `spend_bound_cents` and unchanged `to` and `body`. See [Personal phone plan](/phone-plan) for limits and approval rules.

## Use the phone

Check the Muse credential in Settings \> Connected clients for `phone:read` and `phone:call`; add `phone:text` when creating it only if texts are needed. Replace an older read-only credential and update Muse rather than expecting it to gain permission automatically.

Follow [Your first call](/phone-plan#your-first-call), using the REST routes above instead of MCP tools. The plan, number, owner approval and limits are the same. A connection alone is not a ready phone line. See the [refusal help](/phone-plan#if-a-call-is-refused).

## Disconnect

Open Settings, Connected clients in the Sempera App and revoke the client. That ends its credential at once and leaves every other assistant working.
