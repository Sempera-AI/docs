ChatGPT connects to Sempera Phone as a custom MCP server and signs in with OAuth. Once you approve it, ChatGPT can preview calls and texts for you to approve, start the ones you approved, and read their results.

Status: **Unverified**. The server side is built and tested against the published standards, but no real ChatGPT account has completed the connection yet ([Supported clients](/supported-clients#ai-assistants)). If a screen differs from these steps, tell hello@sempera.org and this page will be corrected.

## Add Sempera as a custom MCP server

1. In ChatGPT, open the place where you add plugins and connectors, choose the plus button, then **Add custom MCP server**.
2. Enter the server URL below and choose **OAuth**. Leave the client ID empty, so ChatGPT registers itself.
3. Create and install it. ChatGPT opens Sempera's consent page.
4. Sign in, check that the request names ChatGPT, choose the workspace and the phone permissions, and approve. Approving charges nothing.

```text
https://api.sempera.org/v1/mcp
```

The consent page shows the redirect `https://chatgpt.com/connector_platform_oauth_redirect` as ChatGPT.

## Permissions

| Permission | What ChatGPT can do with it |
| --- | --- |
| `phone:read` | See the number, the plan state, what is left and the results of calls |
| `phone:call` | Preview, start and cancel calls you approved |
| `phone:text` | Preview and send texts you approved, and read text threads |

A client that asks for nothing gets `phone:read` only. To change permissions, approve ChatGPT again; the new grant replaces the old one.

## Check the connection

Ask the assistant for your Sempera Phone number and what is left this period. That is a read: it places nothing and needs only `phone:read`. The same read over plain HTTP, with a phone credential from Settings, Connected clients:

An ordinary workspace API key is refused on the phone routes: every phone credential is a connected client (an OAuth grant, an MCP connection or a REST credential), so it can be revoked on its own.

## What happens on a call

1. The assistant calls `phone_preview_call` (or `POST /v1/phone-tasks/preview`) with the number, the task, the `permitted_actions` and an optional `max_minutes`. Nothing is dialled or reserved. The answer carries an approval link, or `standing: true` if a standing approval covers that number.
2. You open the link signed in to Sempera, read the exact request and approve or decline. The approval is good for five minutes.
3. The assistant calls `phone_start_call` with the same values. Any change is refused. The task moves to `reserved`, which means queued, not dialling.
4. The assistant follows the task with `phone_get_task` until `completed`, `failed` or `cancelled`. The `result` is marked `untrusted`: it was written from what someone else said.

Texts work the same way with `phone_preview_text` and `phone_send_text`. The full rules, limits and refusal codes are in [Personal phone plan](/phone-plan).

## Before the first call

The plan is not open for purchase yet. When it opens, a first call also needs a number on the account and a published Sempera agent pinned to the plan; until then a start is refused with `PHONE_PLAN_INACTIVE`, `PHONE_NUMBER_MISSING` or `PHONE_AGENT_UNPINNED`. Calls and texts go out only while it is between 9 a.m. and 9 p.m. in both Toronto and Vancouver (noon to 9 p.m. Eastern); outside that window they are refused with `PHONE_OUTSIDE_HOURS`.

## Disconnect

Open Settings, Connected clients in the Sempera App and revoke the client. That ends its credential at once and leaves every other assistant working.
