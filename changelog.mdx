## Deprecation policy

Breaking changes ship as a new major path (`/v2`) with a migration guide, a deprecation notice on the old path and a sunset date announced here at least 90 days ahead. Additive changes (new fields, new routes, new event types) ship on `/v1` without notice and are safe to ignore.

<Update label="Unreleased" description="AI disclosure setting">

- Each agent has an AI disclosure setting (`ai_disclosure` in the draft, `compliance.yaml.ai_disclosure.enabled`), off by default for new and existing agents. On: the agent says it is a virtual assistant right after the owner's greeting, as before. Off: the owner's greeting is said word for word, with no AI sentence added. Changing it is a HIGH-risk change, decided by a named person on Publish and kept in the agent's change and version history. The recording notice is unchanged: it follows the greeting whenever calls are recorded and is never said when they are not. The truthful answer to "are you a person?" does not depend on the setting.

</Update>

<Update label="Unreleased" description="saved links and client guidance">

- Legacy App links retain their query parameters and fragment at the final workspace redirect, including repeated filters. Parameters and anchors explicitly set by a migration take precedence. Sign-in still uses the same-origin return address; a visitor without a workspace still goes to onboarding, without automatic saved-link resumption afterward.
- [Supported clients](/supported-clients) now distinguishes the source-available TypeScript and Python SDKs from package publication. The MCP guide makes the complete bearer header value explicit. No API route, credential boundary or database schema changed.
- `POST /v1/calls` accepts `mode: "prompt"`: the conversation is only `task` (or `settings.prompt`), with `first_sentence`, `voice` and `language` for this call. `agent_id` remains the line for number, consent, do-not-contact, calling hours, caps and billing. A prompt is required. `agent_version`, `production` and `environment` are refused. `prompt_only` is not a field and skips no check. [Sessions and calls](/sessions-and-calls) and [TypeScript and Python SDKs](/sdks).

</Update>

<Update label="2026-11-02" description="recovering a stale scenario save">

- `POST /v2/agents/{agent_id}/scenarios/{id}` keeps its existing revision check and `409 CONFLICT` envelope, adding `reason: stale_scenario` and the current draft `revision` only for a stale save, including a race at the atomic draft write. Other conflicts and missing or foreign pathways disclose no revision. The App asks Keep my changes or Discard changes before recovery.

</Update>

<Update label="2026-11-02" description="Sempera voice and engine identities">

- `GET /v1/voices` accepts Sempera engine aliases in `engine` or `provider`, rejects invalid aliases with `reason: invalid_voice_id`, and answers catalogue refusals in Sempera's words.
- Spec exports and frozen environment settings seal both speech legs' engine and model identities, including retained staging snapshots created before this change. Stored agents, voices and version hashes are unchanged. No data migration is required.
- Conversation details, call-log summaries, live-call engines and voice handovers use Sempera identities for locally served speech too. Advanced views are not an exception. Operators retain the original runtime record.

</Update>

<Update label="2026-10-28" description="voices">

### Changed

- Every voice a customer reads is named by a Sempera voice id (`voice_` then lowercase letters and digits) and neutral fields, never by the speech engine or the engine's own id for the voice: `GET /v1/voices` (each row is `{id, voice_id, name, display_name, description, language, source, production_eligible, preview_available, available}`, plus `visibility` for a custom voice), the Agent's `voice`, a draft's `voice`, a session's `voice.voice_id`, a persona's and a call's voice, and the agent export's `agent.yaml`. The `provider` and `engine` fields of `GET /v1/voices` are removed. A voice of a published Sempera model keeps the name its model lists.
- The ids are stable and safe to store, and one voice has one id whichever transport of an engine it is spoken through. A raw voice id from before this change is still accepted wherever a voice is written (a draft, a session, a favorite, an agent file) and keeps meaning the same voice; reads return only Sempera voice ids.
- An id that looks like a Sempera voice id but is not one is refused the same way everywhere: `400` with `reason: invalid_voice_id` (`code: invalid_voice_id` on the App's own routes), on a draft, a session, a voice's detail and preview, and a favorite.
- A voice refusal is in Sempera's words ("That voice is not in the voice list.") and never repeats the engine or the engine's id for the voice.
- `POST /v1/sessions`: `voice` and `speech_recognition` no longer carry `provider`, `fallback_provider` or `model`, except a leg on a published Sempera model, which is still named by its Sempera model id. `voice.voice_id` is the Sempera voice id.
- `GET` and `PATCH /v1/agents/{id}/draft`: the draft's `fields` name a speech engine (`runtime_tts_provider`, `runtime_tts_fallback`, `runtime_stt_provider` and a speech selection's `provider`) by a sealed Sempera engine name (`engine_` then letters and digits), and a voice by its Sempera voice id. A `PATCH` takes the sealed name or the engine id. The draft summary previews a speech engine by its plain label ("Studio voice", "Standard recognition").
- The runtime reading names a speech engine and its model by a sealed Sempera name too: the `runtime` block's hearing and speaking legs (`options[].value`, `identifier` and `model`, the `configured` and `effective` values, the speaking pace's engine) in the `result` of a draft `PATCH` and on `GET /v1/agents/{id}`. A `PATCH` takes the sealed name back, and the engine id still writes. An option's `reason_detail` is the same owner sentence as its `reason`.
- A refused voice reads by the refusal's code, never its internal sentence: `voice_unknown`, `engine_unavailable`, `engine_not_allowed`, `catalog_unavailable`, `preview_unavailable`, and for a custom voice's consent `consent_no_workspace`, `consent_store_unavailable` and `consent_missing` (as `reason` beside `code: voice_consent_required`).
- Agent files and GitHub sync: `agents/<slug>/agent.yaml` names each voice by its Sempera voice id (`voice: {id, name}`) and each speech engine by its sealed name, so nothing the agent's repository holds names the engine. Importing reads both back to the same runtime values, an older file with raw ids still imports, and the content hash Sempera reports for a file tree is the same in either form. The first sync after this change commits the rewritten `agent.yaml` once.

</Update>

It used to include the engine's or the carrier's own error text, which could name the service it called (2026-09-29, [Text messages](/sms)).
- `agent.published` carries the same `agent_version` object (`id`, `object`, `agent_id`, `version_number`, `created_at`, `spec_hash`, `compiled_artifact_id`) whichever road published. A publish from the App used to send the version ledger's own row, with different key names and internal snapshot hashes ([Webhooks](/webhooks)).
- A webhook endpoint whose stored signing secret cannot be read is never sent an unsigned request: the attempt fails in the delivery log with a sentence saying so. One such endpoint also no longer stops the workspace's other endpoints from hearing the same event.
- Every webhook delivery goes over one guarded road (2026-09-28): the host is resolved and the connection pinned to the address that was checked, an address inside a private network is refused, and a redirect is a failed attempt. A saved endpoint URL with a private address literal, a user name or password, or a bad port is refused with `validation_failed`.
- A trigger's webhook action names one of the workspace's registered webhook endpoints and is signed with that endpoint's own secret; a new `tool` action calls one of the workspace's API request tools. `POST /v1/automation/executions/{id}/retry` sends a failed or stalled webhook or tool run again once, with the same event id (2026-09-28).
- A call's `call.completed` and `call.outcomes` deliveries lose the words read from a call once its transcript is deleted: the stored bodies are emptied, and a later retry of a `call.outcomes` delivery sends the emptied event (2026-09-26).
- A version is named the same way everywhere (2026-09-28): the production pin on `POST /v1/calls` resolves to the version the agent's current build resolved to, not simply the newest ledger row, and a voice or phone call's record names the version it started on, not the one current when it ended.
- Editing a tool or a connection checks its name only inside its own workspace. Another workspace's tool of the same name no longer refuses the edit or reveals that the name exists elsewhere (2026-09-28).
- Evaluation criteria are read and scored from the caller's own workspace only (2026-09-27).
- `openapi.json` names no provider: an operation id that carried a platform name is now `listCitationSchemasListPath`, and a compatibility path whose name carries that platform's name is still served but no longer listed.
- `openapi.json` declares the `branch_id` path parameter (a UUID) on the four `/v2/agents/{uuid}/branches/{branch_id}` routes (rebase preview, rebase, merge and delete), which listed only the agent (2026-09-29). The routes themselves did not change.

<Update label="2026-09" description="the one-API cutover">

- Compatibility `/v2` routes for the console agent, disposition, deployment, batch and analytics reads were added behind the same credential and workspace boundary as `/v1`. They are facades over Sempera-owned stores, not a separate database.
- `api.sempera.org` became the single canonical Sempera API, versioned under `/v1`, with `openapi.json`, `llms.txt` and these guide pages served from it.
- The private server hostname (the retired legacy API hostname, retired 2026-09-14) was migrated behind the canonical API. No customer or developer integration ever targeted it.
- The existing operational routes that the live salon agent's tools call (`/v1/caller/*`, `/v1/catalog/*`, `/v1/center/*`, `/v1/booking/*`, `/v1/messages`) remain in service unchanged as the runtime tool surface; they are internal to Sempera-built agents, are not part of the public contract, and will be folded into Tools when the salon agent is next re-certified.
- Credential classes (developer, runtime, CI, service, admin keys; the browser session token) were introduced with explicit scopes.
- Sempera-signed outbound webhooks were introduced (`X-Sempera-Signature`).
